Status: four source-audited chapters are published under `book/src/windows-platform-shipping/` with compiling anchors from `examples/platform_shipping`. All E2.11 plan boxes remain unchecked because native custom titlebar/decorations, an active OS accessibility adapter, distributable signed/installable release artifacts, and crash collection have not been verified. A local macOS development `.app` exists, signed explicitly ad hoc; it does not satisfy the packaging plan bullet. The example provides anchors `window_options`, `multiple_windows`, `appearance_scale`, `accessible_custom_element`, `diagnostics_setup`, and `platform_shipping_main`. Four library tests check independent window roots, appearance/scale reads, direct AccessKit node semantics, and local diagnostic records. The custom status is noninteractive; optional tree JSON is absent when the headless adapter is inactive. The screenshot checks only the main view on macOS at 760 × 540 output pixels, light appearance, and reported native scale 2.0 on this host; it does not show two native titlebars. The local logger test catches a panic and stores its message directly, but does not exercise the installed hook or collect a process crash. The packaging chapter documents the built, ad-hoc-signed local development bundle and official distribution guidance. On 2026-09-24, the assembled bundle launched in this Mac desktop session: native accessibility reported a standard `Diagnostics` window, and a screenshot showed its rendered diagnostics view. This is a single local launch, not clean-machine installation or release verification. Chapters have no handwritten Rust. The page about windows cites a later official Zed floating-window report with its narrower scope; the other pages use official platform guidance or leave out a Zed report where none matched.
