# E2.7 interaction source audit and fixture evidence

Status: `examples/interaction` and seven published chapters under `src/interaction/` exist. All eight source anchors mark real code. The seven library tests, both macOS screenshot comparisons, the book checker, mdBook build, and built-HTML check pass. The idle and keyboard screenshots are 640 × 520 at scale 1.0. The GPUI Kit context-menu popup has a headless keyboard-selection/activation test; native app-menu selection, an accessibility snapshot, reverse focus traversal, and real file-manager exchange remain unverified. The workspace pins `gpui-pre = 0.3.5`, which corresponds to Zed commit [`d89e9c2124b2786a390c7a451c7488601b4da2e1`](https://github.com/zed-industries/zed/tree/d89e9c2124b2786a390c7a451c7488601b4da2e1). Check public names against the [inventory](inventory.md) before writing chapters. In this pin, E1's supplied headless renderer captures pixels on macOS only; see [the tested spike](../docs/spikes/headless.md).

## Implemented fixture contract

The workspace crate `examples/interaction` has named source anchors `interaction_actions`, `interaction_focus`, `interaction_list`, `interaction_pointer`, `interaction_drag_drop`, `interaction_clipboard`, `interaction_menus`, and `interaction_main`. Chapter Rust fences use `{{#include}}` directives from those compiled regions. Its harness test compares the idle and keyboard baselines under `book/src/images/`; inspect diffs before baseline updates.

The fixture validates a caller-selected alternate down binding (`ctrl-k` in the test) and Enter activation, row hover/press/click, typed row reordering, a synthetic `FileDropEvent` over the painted target, and test-clipboard text and empty cases. `main` reads `MKIT_MOVE_DOWN_KEY` at startup and the help text shows the selected key. The application menu is registered and `get_menus()` returns one menu in the headless setup; a separate headless test opens the GPUI Kit row popup and confirms Enter activates its action. Native application-menu selection remains manual-only. The external-path test exercises GPUI's event path, not a file manager or another OS process. The file target records names only on drop; it does not record paths on Entered or Pending, so it has no live preview. The fixture also has no outbound `external_drag_payload`. The focus test confirms initial list focus and one `Window::focus_next` move to a help target. It does not test Shift-Tab or reverse traversal. The listbox roles and selected properties are set, but no accessibility snapshot is available yet. The keyboard screenshot dispatches Down and captures the selected second row with a visible focus ring.

## Pinned platform boundary and manual checks

The [macOS platform implementation](https://github.com/zed-industries/zed/blob/d89e9c2124b2786a390c7a451c7488601b4da2e1/crates/gpui_macos/src/platform.rs#L1077-L1089) creates and installs the native main menu. The [Windows](https://github.com/zed-industries/zed/blob/d89e9c2124b2786a390c7a451c7488601b4da2e1/crates/gpui_windows/src/platform.rs#L811-L819) and [Linux](https://github.com/zed-industries/zed/blob/d89e9c2124b2786a390c7a451c7488601b4da2e1/crates/gpui_linux/src/linux/platform.rs#L683-L691) implementations store `set_menus` definitions but do not create a visible menu bar in those methods. The registered menu therefore demonstrates a native bar only in the macOS source path; a `get_menus()` assertion establishes registration, not selection. The [macOS file-drop callbacks](https://github.com/zed-industries/zed/blob/d89e9c2124b2786a390c7a451c7488601b4da2e1/crates/gpui_macos/src/window.rs#L3500-L3545) and [Windows file-drop callbacks](https://github.com/zed-industries/zed/blob/d89e9c2124b2786a390c7a451c7488601b4da2e1/crates/gpui_windows/src/window.rs#L1170-L1258) construct `FileDropEvent` values, but those source paths do not verify this fixture's exchange with Finder or Explorer.

The [menus chapter](src/interaction/menus.md#native-verification) gives a macOS menu-selection and popup procedure. The [drag-and-drop chapter](src/interaction/drag-and-drop.md#native-verification) gives a file-manager drop, cancellation, and target procedure. A verifier should record OS version, source app or file manager, actual visible result, accessibility result where relevant, and any permission prompt. No result from those procedures is recorded yet; the attempted macOS desktop run was blocked by the locked host.
