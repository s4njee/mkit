# Size and scroll a settings area

## What you'll build

Place the settings rows inside a bounded content area that can scroll when the rows exceed its height. Run `cargo run -p mkit-example-settings-screen` from the workspace root.

![Settings screen with the Display section continuing below the bottom edge of the bounded content area](../images/settings-screen.png)

![Same settings screen scrolled to the bottom, showing the sync card and pinned workspaces](../images/settings-screen-scrolled.png)

## Concept

[`Styled`](../appendices/api-inventory.md) provides size and spacing builders for an element's layout style. Width and height constrain its box; padding creates space inside it, and gap separates flex or grid children. The pinned [`Style`](https://github.com/zed-industries/zed/blob/d89e9c2124b2786a390c7a451c7488601b4da2e1/crates/gpui/src/style.rs#L180-L270) stores these values before GPUI requests layout. Several fluent sizing and spacing methods are generated by macros in `Styled`, so use the compiling example as the guide to the exact names.

Scrolling requires a bounded viewport and overflowing content. [`InteractiveElement::overflow_y_scroll`](https://github.com/zed-industries/zed/blob/d89e9c2124b2786a390c7a451c7488601b4da2e1/crates/gpui/src/elements/div.rs#L1518-L1535) sets vertical overflow to `Scroll`. GPUI then maps its [`Overflow`](https://github.com/zed-industries/zed/blob/d89e9c2124b2786a390c7a451c7488601b4da2e1/crates/gpui/src/style.rs#L1311-L1320) to Taffy's layout value. This chapter concerns the container's scrolling; scrollbar appearance belongs to the active theme and renderer.

## Minimal compiling example

The scroll container is part of the same settings-screen crate:

```rust
{{#include ../../../examples/settings_screen/src/lib.rs:settings_screen_scroll}}
```

Run `cargo run -p mkit-example-settings-screen`. `cargo test -p mkit-example-settings-screen --lib --locked` checks that the content overflows and a simulated wheel event moves the scroll offset. On macOS, `cargo test -p mkit-example-settings-screen --test screenshot --locked` compares top and bottom 1920 × 1280 captures at scale 2.0; the harness scrolls the view to the bottom between captures. Windows and Linux compile the screenshot test but report unsupported headless capture.

## How it works

The outer layout determines the available height. The included content `div` uses `flex_1().min_h_0()` to take the remaining bounded space, adds `p_7()` interior spacing, and sets `overflow_y_scroll()`. Its content groups extend below the initial viewport. Scroll input changes which portion is visible while the container keeps its allotted size.

[`Styled::scrollbar_width`](https://github.com/zed-industries/zed/blob/d89e9c2124b2786a390c7a451c7488601b4da2e1/crates/gpui/src/styled.rs#L60-L68) reserves space only if overflow is `Scroll`; setting the width by itself does not make a box scrollable. The library test sends a wheel event and checks that the tracked offset becomes negative. The harness uses the view's `scroll_to_bottom()` helper to capture lower content. Neither test checks trackpad behavior.

## Exercises

1. Reduce the content area's height, run the app, and scroll to the last setting. Confirm it remains reachable; restore the original height before the screenshot comparison.
2. Remove the vertical scroll builder temporarily and run `cargo test -p mkit-example-settings-screen --lib --locked`. The scroll-extent or offset assertion should fail. Restore the builder and confirm both tests pass again.
