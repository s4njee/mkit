# E2.14 comparison guide evidence

Status: three source-audited guides are published under `book/src/coming-from/` and listed in `SUMMARY.md`. Framework pages were checked on 2026-09-24; their versions and wording can change. GPUI claims use the workspace's pinned `gpui-pre = 0.3.5` source at [Zed commit `d89e9c2124b2786a390c7a451c7488601b4da2e1`](https://github.com/zed-industries/zed/tree/d89e9c2124b2786a390c7a451c7488601b4da2e1).

| Guide | Official framework evidence | Compiling GPUI evidence | Boundary to keep |
| --- | --- | --- | --- |
| React | [React state](https://react.dev/reference/react/useState), [effects](https://react.dev/reference/react/useEffect), [state ownership](https://react.dev/learn/sharing-state-between-components) | `examples/reactivity_views` anchors `reactivity_views_events`, `reactivity_views_view`, `reactivity_views_main`; retained [`Entity`](https://github.com/zed-industries/zed/blob/d89e9c2124b2786a390c7a451c7488601b4da2e1/crates/gpui/src/app/entity.rs), [`observe`/`subscribe`](https://github.com/zed-industries/zed/blob/d89e9c2124b2786a390c7a451c7488601b4da2e1/crates/gpui/src/app/context.rs#L60-L123) | GPUI subscriptions are callback handles, not a drop-in React `useEffect` with dependency arrays. GPUI rendering is immediate-style over retained entity state, with cached unchanged subtrees. |
| Tauri | [Architecture](https://v2.tauri.app/concept/architecture/), [process model](https://v2.tauri.app/concept/process-model/), [IPC](https://v2.tauri.app/concept/inter-process-communication/) | `examples/counter` anchors `counter_view`, `counter_main` and screenshot; pinned [`Render`](https://github.com/zed-industries/zed/blob/d89e9c2124b2786a390c7a451c7488601b4da2e1/crates/gpui/src/element.rs#L160-L166) | The book's GPUI example is one Rust application process with native GPUI elements. This does not assert that every GPUI application has only one OS process or that GPUI offers Tauri webview, JavaScript, or IPC APIs. |
| iced and egui | [iced 0.14 pocket guide](https://docs.rs/iced/latest/iced/), [egui immediate mode](https://docs.rs/egui/latest/egui/#understanding-immediate-mode) | `examples/counter` anchors and screenshot; pinned [`Render`](https://github.com/zed-industries/zed/blob/d89e9c2124b2786a390c7a451c7488601b4da2e1/crates/gpui/src/element.rs#L160-L166) and [view cache](https://github.com/zed-industries/zed/blob/d89e9c2124b2786a390c7a451c7488601b4da2e1/crates/gpui/src/view.rs#L380-L415) | iced has explicit state/message/update/view and tasks; egui describes immediate-mode UI. GPUI describes elements from retained entities and can reuse unchanged view work. It is not a pure egui-style frame callback or an iced `Message`/`update` API. |
