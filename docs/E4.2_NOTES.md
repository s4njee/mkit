# E4.2 focus management design and evidence

`mkit-core::focus` holds shared keyboard-focus rules for dialogs, popovers, toolbars, lists, and grids. GPUI 0.3.5 provides `FocusHandle`, `track_focus`, tab stops, tab groups, and `focus_visible`. The mkit layer adds an ordered focus scope that wraps Tab and Shift+Tab inside an active context; a roving group that keeps only one item in the tab order; and a focus-ring helper that reads the active mkit theme's focus color and border width.

## Contract

- A dialog or popover owns a `FocusScope` with its enabled focus handles in visual order. Its view binds rebindable forward/backward actions in a scoped key context, calls the scope on those actions, and restores its opener's focus when it closes. Escape and outside-click dismissal belong to the overlay component.
- A toolbar, list, or grid owns a `RovingFocus` for enabled items. One item is a tab stop. Render each item using `RovingFocus::handle(index)` so its tab-stop setting follows the active item; clones supplied at construction do not update. Arrow/Home/End actions change the active item and focus it; grid owners pass their column count for vertical movement. An item that becomes disabled must be removed or replaced in the group before rendering.
- A focusable element calls `focus_visible_with_theme` after `track_focus`, using `Theme.colors.focus` and `Theme.borders.strong`. GPUI only applies that style when keyboard navigation caused focus, so pointer focus does not acquire the same ring.
- These helpers do not set accessibility roles or names. Each component sets those semantics and a stable ID, and keeps keyboard actions rebindable through a `key_context` and typed GPUI actions.

`cargo test -p mkit-core --locked` passed 18 tests on 2026-09-24. Headless rendered-window tests dispatch Tab, Shift+Tab, and Right through the registered key contexts and assert wrap, focus movement, and the single rendered roving tab stop. The helper's token lookup compiles, but there is no focus-ring screenshot across light, dark, and high-contrast themes. Native keyboard focus, screen-reader behavior, multi-window restoration, and visual contrast still need separate harness or desktop evidence. Public API and keyboard contracts require maintainer review.
