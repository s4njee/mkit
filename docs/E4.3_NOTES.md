# E4.3 overlays and positioning notes

`mkit-core::overlay` centralizes a pure placement policy for anchored popovers:
try the requested side, flip vertically if that side does not fit and its
opposite does, then shift the rectangle into the window's margin-safe area.
Horizontal alignment can target the trigger's start or end edge. Oversized
overlays are pinned to the leading margin; the caller still needs to constrain
their dimensions or make their contents scrollable.

`deferred_at` composes the result with GPUI 0.3.5 `anchored()` and `deferred()`.
GPUI's anchored element supports either corner switching or snapping to the
window edge; this helper computes flip and shift before rendering and uses
`snap_to_window_with_margin` as a final bounds guard. Deferred draw priorities
are exposed for tooltip, popover, menu, and modal stacking. Apps can use those
priorities to establish consistent relative order.

GPUI `deferred` controls paint order; it does not provide overlay ownership,
outside-click dismissal, Escape handling, focus trapping, or modal input
blocking. The shared `DismissalPolicy` records whether outside pointer presses
and Escape should dismiss a particular overlay. `should_dismiss` decides
whether an input event requests closure under that policy.

The live fixture is intended to establish a component-level wiring pattern for
outside press capture, a rebindable Escape action, and topmost-only dismissal
for nested overlays. GPUI 0.3.5 exposes `InteractiveElement::on_mouse_down_out`
for pointer presses outside an element and key/action handlers for keyboard
input. Register Escape through the component's `key_context`/action contract so
apps can rebind it. `should_dismiss` does not install handlers, consume events,
stop propagation, trap focus, or block input behind the overlay. A backdrop or
explicit hit target is needed if outside presses must be intercepted.

The interaction fixture checks one outside press dismisses only the top nested
overlay, a caller-selected `ctrl-e` binding dismisses one layer while the
default Escape binding does nothing, and an outside press reaches an uncovered
underlying control. It also checks actual `Window::painted_quads()` draw orders
for overlapping fixture panels: the higher-priority inner menu quad is painted
after the lower-priority popover quad. The latter relies on GPUI's test-only
painted-quad inspection; no raster screenshot is needed for this ordering
assertion.

These checks run in the GPUI headless test window. They verify dispatched test
events and scene draw-order metadata, not native OS input or screen-reader
behavior. The underlying control is outside the overlay bounds, so modal input
blocking behind an overlay remains unverified. A modal must provide and test an
explicit backdrop/input barrier if it requires that guarantee.

## Nested overlay visual preview

`OverlayDismissalFixture::nested_open()` builds the outer popover and inner
menu in a stable open state. The fixture reads background, surface, accent,
text, and border colors from the mkit `Theme` global; the screenshot setup
installs `LIGHT`. The anchored positions and panel dimensions are fixed for this
preview so both overlay labels and the outer trigger remain visible in the
640 × 480 capture.

The checked-in reference is [`e4-overlay-nested.png`](../book/src/images/e4-overlay-nested.png),
captured at scale 1.0. The screenshot target compares this light capture with
`PixelTolerance { channel_delta: 2, max_different_pixels: 8 }`. It also captures
dark and high-contrast at scale 1.0 and light at scale 2.0 (1280 × 960); those
three variants assert dimensions and are written to the system temp directory
when `UPDATE_SNAPSHOTS=1`. All three were visually inspected. They are not
checked-in baselines, so automated pixel comparison currently covers only the
light scale-1 image. The target reports `UnsupportedPlatform` outside macOS,
matching GPUI 0.3.5's renderer limit.

Verification: `UPDATE_SNAPSHOTS=1 cargo test -p mkit-example-interaction --test
e4_overlay_screenshot --locked` generated the baseline and theme/scale previews;
`cargo test -p mkit-example-interaction --test e4_overlay_screenshot --locked`
then passed its baseline comparison. The fixture is a static visual preview;
it does not establish native desktop positioning, modal blocking, focus
behavior, or an accessibility snapshot.
