# E4.5 accessibility helpers notes

`mkit-core::a11y::AccessibilityExt` provides short helpers for the accessibility
properties available on GPUI 0.3.5 stateful interactive elements: role, name,
description, string and numeric value, selected, expanded, and toggled state.
Each helper delegates directly to GPUI's `StatefulInteractiveElement` API.
This keeps the crate from maintaining a parallel role or state model.

GPUI emits accessibility nodes for elements with a stable element id and a
non-`GenericContainer` role. The helper methods do not add ids, infer roles,
create focus behavior, or implement accessibility actions; component authors
must supply those as appropriate. The role API accepts AccessKit's `Role`, and
the state helpers expose only properties present in the pinned GPUI API.

## Announcement helper contract

The API review found a supported path in pinned GPUI 0.3.5: an element can
contribute a synthetic-node callback with `StatefulInteractiveElement::a11y_synthetic_children`,
and the callback receives a public `A11ySubtreeBuilder` whose `parent_node()`
returns the current `accesskit::Node`. AccessKit 0.24.1 exposes
`Node::set_live(Live::{Polite, Assertive})`. The helper contract is to set that
live property on the element's own node. Components must still provide a stable
`.id(...)` and a non-generic `.role(...)`; GPUI only invokes the synthetic child
callback for nodes that are present in the accessibility tree.

The pinned adapter sources consume this property with platform differences:
`accesskit_macos 0.26.3` queues an announcement when a live node is added or its
value/live mode changes; `accesskit_windows 0.34.0` emits
`UIA_LiveRegionChangedEvent` when a named live node is added or its accessible
name/live mode changes; and `accesskit_atspi_common 0.19.1` emits an AT-SPI
announcement event when a live node is added. Its `node_updated` implementation
does not emit an announcement for an existing node's value/name change. That
means the stable-node update pattern is not source-verified as an AT-SPI
announcement on this adapter version. Provide a meaningful accessible name and
updated value, and verify actual speech with the target OS and assistive
technology. Do not claim consistent cross-platform speech from the shared
AccessKit property alone.

`a11y_live_region(priority)` accepts an explicit polite or assertive choice. A
toast/status caller should pair it with an appropriate role and accessible
name/value. Keep a stable id on a persistent status node and update its
accessible value with each new status. A stateful GPUI entity should update the
status model and call `cx.notify()` so GPUI rebuilds the same identified node
with the new value. The example contract is a persistent `Role::Status` node
with stable id `e4-operation-status`, polite priority, and an accessible name
`Operation status: {message}` plus value `{message}` updated for each distinct
status. Changing the name as well as the value gives name-driven adapters a
current message to announce. The helper reports AccessKit semantics in the
tree; it does not promise a specific spoken phrase or delivery timing. Whether a given assistive
technology announces a particular update remains platform behavior and requires
manual VoiceOver, NVDA, and AT-SPI review.

GPUI 0.3.5 stores only one `a11y_synthetic_children` callback per element; a
later call replaces an earlier callback. Consequently, `a11y_live_region(...)`
must not be combined on the same element with another call to
`a11y_synthetic_children(...)`. Put the live-region helper last only when no
other synthetic-child callback is needed. If an element needs both behaviors,
the caller must currently use one callback that applies both mutations; the
core helper does not offer a composition API.

## Verification limits

The state example captures an initial
[`Waiting for upload`](../book/src/images/e4-status-initial.png) state and an
updated [`Upload complete`](../book/src/images/e4-status-updated.png) state at
640 × 400, scale 1.0, using the light theme and the macOS Metal headless
renderer. These are rendered-state baselines; they do not
prove an accessibility tree update or spoken output.

Tests cover the status entity's value changes and notification-triggered
rendering, and assert polite/assertive AccessKit property mapping. The
workspace's stock GPUI test window reports accessibility inactive and provides
no captured tree, so the live-region node cannot currently be verified in a
rendered GPUI accessibility snapshot with the harness. No native OS announcement
or screen-reader behavior has been tested. Keep those as explicit review gaps;
`Role::Status` by itself is not the live-region contract.
