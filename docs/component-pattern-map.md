# Component pattern map (E5.2)

This map covers the components planned in [E7 and E8](../plan.md#e7--everyday-components). An APG pattern is a behavioral reference for the named interaction, not a mandate to reproduce browser/DOM implementation details. Where APG has no equivalent, the row names the nearest lower-level pattern and marks the added behavior as custom. Specs should link back here and state any component-specific decisions.

## Planned component mapping

| Planned component | APG pattern or platform convention | GPUI desktop mapping and differences to record in the spec |
|---|---|---|
| Button; icon button | [Button](https://www.w3.org/WAI/ARIA/apg/patterns/button/) | Invoke on Enter/Space. Icon-only buttons need an accessible name. A loading button remains identifiable and its busy/disabled behavior must be explicit. Use the platform's standard command shortcuts where applicable. |
| Toggle button | [Button](https://www.w3.org/WAI/ARIA/apg/patterns/button/) (toggle button) | Expose pressed state; keep the label stable while toggled, as APG recommends. |
| Toggle group | [Toolbar](https://www.w3.org/WAI/ARIA/apg/patterns/toolbar/) when it is a compact related-control group; [Radio Group](https://www.w3.org/WAI/ARIA/apg/patterns/radio/) when exactly one option is selected; otherwise compose Button patterns | The spec must say whether the group is a toolbar, a single-choice group, or independent toggles. Do not make Tab traverse every child when using toolbar-style roving focus. |
| Checkbox | [Checkbox](https://www.w3.org/WAI/ARIA/apg/patterns/checkbox/) | Space toggles; support mixed state where parent/aggregate selection requires it. |
| Radio group | [Radio Group](https://www.w3.org/WAI/ARIA/apg/patterns/radio/) | Arrow keys move and select within the group; Tab enters/leaves the group. Account for platform focus conventions, and do not turn radio choices into menu items. |
| Switch | [Switch](https://www.w3.org/WAI/ARIA/apg/patterns/switch/) | Binary on/off control. Keep its accessible label stable across state changes. |
| Slider | [Slider](https://www.w3.org/WAI/ARIA/apg/patterns/slider/) | Preserve arrow, Home/End, and optional Page Up/Down behavior; modifier-based precision is an app convention and must be documented. Expose min, max, value, and meaningful value text. |
| Progress | No dedicated APG authoring pattern; use the [progressbar role guidance](https://www.w3.org/TR/wai-aria-1.2/#progressbar) | Read-only progress is not a slider. Distinguish determinate from indeterminate progress and provide a name; do not take keyboard focus unless the surrounding interaction requires it. |
| Single-line text field; text area | Text entry is a platform text-control convention; [Textbox role guidance](https://www.w3.org/TR/wai-aria-1.2/#textbox) | Preserve native text editing, selection, clipboard, undo, IME composition, and platform navigation keys. APG composite-widget arrow-key behavior must not override caret movement. Multiline fields expose multiline semantics. |
| Select (select-only) | [Combobox](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/) select-only variant; popup uses [Listbox](https://www.w3.org/WAI/ARIA/apg/patterns/listbox/) | Keep value distinct from accessible name. Popup navigation and commit/cancel behavior need an explicit spec; Escape should cancel an uncommitted exploration when the control preserves the previous value. |
| Editable combobox with filtering | [Combobox](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/) and [Listbox](https://www.w3.org/WAI/ARIA/apg/patterns/listbox/) popup | Text editing remains ordinary text editing; arrows navigate suggestions according to the chosen APG combobox variant. Virtualization must preserve active option identity and accessibility announcements. |
| Multi-select | [Listbox](https://www.w3.org/WAI/ARIA/apg/patterns/listbox/) multi-select, optionally combined with [Combobox](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/) for filtering | Specify modifier-key selection and whether arrows change selection or only the active item. Support platform selection conventions without losing keyboard access to each option. |
| Dropdown menu; context menu; submenu; checkable menu item | [Menu Button](https://www.w3.org/WAI/ARIA/apg/patterns/menu-button/) and [Menu and Menubar](https://www.w3.org/WAI/ARIA/apg/patterns/menubar/) | Use menu semantics for command menus, not ordinary navigation lists. Support Escape and return focus to the opener/context; right-click and platform context-menu keys open context menus. Native menu bars and app-level shortcuts are OS integration points, not popup-menu details. Checkable items retain menu focus after toggling when appropriate. |
| Tooltip | [Tooltip](https://www.w3.org/WAI/ARIA/apg/patterns/tooltip/) | Show on hover and keyboard focus, dismiss with Escape, and do not move focus into the tooltip. Do not use it as the only way to expose essential instructions or actions. |
| Popover | No single APG pattern: choose [Dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/) only when it is a dialog; otherwise use a named non-modal disclosure/region convention | A non-modal popover does not automatically trap focus. Specify dismissal, focus return, outside-click policy, and whether interaction may continue in the owner window. |
| Dialog; sheet | [Dialog (Modal)](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/) when modal; otherwise a non-modal dialog convention | Modality, focus entry/containment/return, Escape, and window close behavior must be explicit. A sheet is a presentation style, not a separate keyboard pattern. Desktop sheets may be resizable or attached to a window; document those differences. |
| Toast | No APG widget pattern; use [Alert](https://www.w3.org/WAI/ARIA/apg/patterns/alert/) for urgent, brief announcements or [Status](https://www.w3.org/TR/wai-aria-1.2/#status) for non-urgent updates | Avoid stealing keyboard focus. Specify announcement urgency, timeout/persistence, and whether actions in the toast are keyboard reachable. |
| Tabs | [Tabs](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/) | Specify automatic or manual activation. Arrow keys move among tabs; Home/End may be supported. Respect platform focus traversal and allow panels to contain normal controls. |
| Sidebar | No single APG pattern: usually [Navigation](https://www.w3.org/WAI/ARIA/apg/patterns/landmarks/) with ordinary buttons/links; use [Tree View](https://www.w3.org/WAI/ARIA/apg/patterns/treeview/) only for genuinely hierarchical items | A navigation sidebar is not a tree merely because it has indentation. For desktop app panes, specify focus entry, collapse, selection, and whether the pane itself is a navigational landmark. |
| Breadcrumbs | [Breadcrumb](https://www.w3.org/WAI/ARIA/apg/patterns/breadcrumb/) | Treat ancestors as navigation and current location as current; do not add tree-style arrow navigation. |
| Segmented control | [Radio Group](https://www.w3.org/WAI/ARIA/apg/patterns/radio/) for mutually exclusive values; [Toolbar](https://www.w3.org/WAI/ARIA/apg/patterns/toolbar/) for a command group | State which model applies. macOS-style segmented controls can switch a view or invoke a command; only the former is a single-choice value control. |
| Virtual list | [Listbox](https://www.w3.org/WAI/ARIA/apg/patterns/listbox/) if options are selectable; [Feed](https://www.w3.org/WAI/ARIA/apg/patterns/feed/) only for a streaming article feed; otherwise custom collection convention | Specify whether focus lands on rows or remains on a container, selection model, type-ahead, and behavior as virtualized items enter/leave the rendered range. A generic list is not automatically a listbox. |
| Tree | [Tree View](https://www.w3.org/WAI/ARIA/apg/patterns/treeview/) | Use roving focus/active descendant and documented arrow-key expansion/collapse. Lazy loading must announce loading and preserve node identity/focus. |
| Data table | [Grid](https://www.w3.org/WAI/ARIA/apg/patterns/grid/) for interactive cells; [Table](https://www.w3.org/WAI/ARIA/apg/patterns/table/) for static tabular information | A sortable, resizable, selectable table is usually a grid. Specify cell-vs-row focus, selection, sorting, resize handles, and how Tab enters/exits editing so arrow keys remain useful for navigation and text editing. |
| Split pane | [Window Splitter](https://www.w3.org/WAI/ARIA/apg/patterns/windowsplitter/) | Expose orientation and current/min/max value. Provide keyboard resizing as well as pointer resizing; describe collapsed-pane behavior. |
| Scroll area | Platform scrolling convention; no APG widget pattern | Preserve platform wheel/trackpad scrolling and keyboard scrolling. A scroll container should not add a Tab stop unless users need a keyboard entry point to otherwise unreachable content. |
| Form layout | No widget pattern; use [Form](https://www.w3.org/WAI/ARIA/apg/patterns/landmarks/) landmark convention where appropriate and label/description relationships | Layout helper only. Ensure labels, descriptions, errors, and controls are associated; do not imply every form is a landmark. |
| Separator | No APG pattern; use the [separator role](https://www.w3.org/TR/wai-aria-1.2/#separator) when structural; [Window Splitter](https://www.w3.org/WAI/ARIA/apg/patterns/windowsplitter/) when draggable | A visual divider is not focusable. A draggable divider is an interactive splitter with value and keyboard behavior. |
| Calendar | [Date Picker Dialog example](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/examples/datepicker-dialog/) date grid; [Grid](https://www.w3.org/WAI/ARIA/apg/patterns/grid/) | One Tab stop with roving focus on the active date: arrows move by day/week, Page Up/Down by month, Shift+Page Up/Down by year, Home/End to the week boundaries, Enter/Space select. Record the first day of week and app-supplied month/weekday names (no hard-coded English), min/max and disabled dates (skipped by navigation, exposed as disabled), day clamping on month moves, range anchor and completion, and the date type. |
| Date picker; date range picker | [Date Picker Dialog example](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/examples/datepicker-dialog/) for the field, calendar button, and grid; typed entry follows the text field row | Keep native text editing and IME; parsing and formatting are app policy, and drafts commit on Enter or calendar selection, not per keystroke. Record the open shortcut, Escape restoring the prior value, Tab/outside-click dismissal without commit, and focus return to the input. APG's example is a modal dialog: state whether the desktop surface is modal or a non-modal anchored popup. Ranges: which endpoint the next choice edits, one shared calendar, and incomplete-range validation. |
| Time field; date-time field | [Spinbutton](https://www.w3.org/WAI/ARIA/apg/patterns/spinbutton/) per segment inside a named group; segment movement follows the platform segmented date/time input convention | Left/Right move between segments; Up/Down step; Home/End go to the segment min/max; digits replace a segment. Record 12/24-hour display, localized AM/PM and separator labels, step and larger-step modifier, min/max and clamping, when a typed draft commits, and value text per segment. The date-time field composes the Date picker row: state whether date and time commit separately or atomically, and add no competing key handlers. |
| Disclosure | [Disclosure](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/) | A button trigger toggles on Enter/Space and exposes expanded state; no arrow keys. Record whether collapsed content leaves the focus order and accessibility tree (and who owns stateful content), the trigger-to-panel relation where the accessibility bridge supports it, and optional motion that does not delay visibility changes. |
| Accordion | [Accordion](https://www.w3.org/WAI/ARIA/apg/patterns/accordion/) | Header buttons expose expanded state and toggle on Enter/Space. Specify single or multiple expansion, whether the only open item may collapse, and whether APG's optional arrow/Home/End header navigation is offered or plain Tab order is used. Disabled items and collapsed panels follow the Disclosure row. |
| Toolbar | [Toolbar](https://www.w3.org/WAI/ARIA/apg/patterns/toolbar/) | One Tab stop with roving focus; orientation sets the arrow axis, Home/End reach the ends, and disabled items are skipped. Specify wrapping, how embedded toggle groups and separators behave, which items may overflow, how the overflow trigger joins the roving order and uses menu semantics (see the Dropdown menu row), and focus after the overflow menu closes. Expose the toolbar name and orientation. |
| Badge | No APG pattern; static text content | Not focusable and not a live region. Record decorative versus informative use (name from visible text or an override), the count maximum and overflow label, app-owned number formatting, and a text or shape cue so status is not color-only. A change that must be announced belongs in a Status region owned by the app. |
| Avatar | No APG pattern; [img role](https://www.w3.org/TR/wai-aria-1.2/#img) with alternative text | Not focusable. Record fallback naming: the caller's name, then initials, then decorative when neither is supplied. Image loading, load failure, and deriving initials from a name are app-owned. |
| Key hint | No APG pattern; displayed shortcut text (the bound control owns [`aria-keyshortcuts`](https://www.w3.org/TR/wai-aria-1.2/#aria-keyshortcuts)) | Presentational: not focusable and binds no action. Record platform modifier names, glyphs, and order (macOS symbols versus Ctrl/Alt text), localized key names, and one spoken name for the whole chord; keycaps do not create nested accessibility nodes. |
| Link | [Link](https://www.w3.org/WAI/ARIA/apg/patterns/link/) | Enter activates; Space does not. Use a link for navigation and a button for actions. Record how the destination opens (app callback, in-app navigation, or the system browser for external URLs), who owns visited state, and disabled-link focus semantics. |
| Inline alert | [Alert](https://www.w3.org/WAI/ARIA/apg/patterns/alert/) for urgent messages; [Status](https://www.w3.org/TR/wai-aria-1.2/#status) for non-urgent ones | Never moves focus. Record the severity-to-politeness mapping, that a message already present when a view appears may not be announced, controlled/uncontrolled dismissal and focus after dismissal, and keyboard access to actions. Severity is not conveyed by color alone. |
| Empty state | No APG pattern; a named [group](https://www.w3.org/TR/wai-aria-1.2/#group) whose actions follow their own rows | Not interactive itself. Label by the title, expose the description, keep the icon decorative unless the caller names it, and keep actions in reading order. Record whether a filter that empties a view announces the empty state. |
| Search field | Single-line text field row with the [searchbox role](https://www.w3.org/TR/wai-aria-1.2/#searchbox); use the Editable combobox row if it shows suggestions | Keep native text editing and IME. Record Escape clearing a non-empty query, clear-button visibility and focus return, debounce versus immediate change events, a rebindable focus shortcut (Cmd+F/Ctrl+F may conflict with app Find), and a polite result-count status. State the role mapping if searchbox is unavailable. |
| Tag input | [Combobox](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/) editor with [Listbox](https://www.w3.org/WAI/ARIA/apg/patterns/listbox/) suggestions; tags as a list with named remove buttons | Focus stays in the editor; tag selection is virtual. Record commit keys (Enter, comma or a locale-appropriate separator, never during IME composition), Backspace on an empty editor selecting then removing the last tag, Left/Right/Delete only when the editor is empty, duplicate and max-count rejection, per-tag validation, and announcements for selection and rejection. |
| File drop zone | No APG pattern; platform drag-and-drop convention with a [Button](https://www.w3.org/WAI/ARIA/apg/patterns/button/) and [Status](https://www.w3.org/TR/wai-aria-1.2/#status) feedback | Dropping is never the only path: a named Browse button opens the native file dialog. Record accepted types (native dialog filters may be unavailable, so paths are filtered after selection), single or multiple, directories, accept/reject cues that are not color-only, polite accept/reject announcements, and that the component handles paths without reading contents. |
| File field | No APG pattern; labelled group with [Button](https://www.w3.org/WAI/ARIA/apg/patterns/button/) controls and [Status](https://www.w3.org/TR/wai-aria-1.2/#status) messages | Browse opens the native file dialog, and cancel leaves the selection unchanged. Each file has a remove button named with the file. Record focus after removal, accepted-type and limit descriptions, and rejection reporting. File rows are not a listbox. |
| Reorderable list | [Listbox rearrangeable options example](https://www.w3.org/WAI/ARIA/apg/patterns/listbox/examples/listbox-rearrangeable/) for keyboard moves; list/list item semantics when rows are not selectable options | Every drag reorder needs a keyboard move; name its modifier and avoid plain arrows and text-editing shortcuts. Record listbox versus list semantics, the drop indicator and invalid targets, position and set size, how moves are announced, controlled acknowledgement, and virtualization or offscreen limits. |
| Menu bar | [Menu and Menubar](https://www.w3.org/WAI/ARIA/apg/patterns/menubar/) | State whether the menu bar is platform-owned (the native macOS app menu) or drawn in the window (Windows and Linux). For the in-window bar, record focus entry (Alt, and whether F10 is bound per Windows convention), mnemonics, Left/Right with an open popup following, Down/Up opening at the first/last item, Escape returning to the header, and Tab closing. Record how one menu model drives both paths and what the native path cannot express. |
| Status bar | No APG pattern; [Status](https://www.w3.org/TR/wai-aria-1.2/#status) text, the Progress row, and ordinary buttons | Not a composite or Tab stop; only supplied controls take focus, in order. Updates are polite and never move focus. Record collapse priority at narrow widths (omission or an overflow menu) and that collapsed items leave the accessibility tree. |
| Stepper (multi-step flow) | No APG pattern; named group with an ordered step list, [Button](https://www.w3.org/WAI/ARIA/apg/patterns/button/) navigation, and [Status](https://www.w3.org/TR/wai-aria-1.2/#status) errors; mark the current step as [current step](https://www.w3.org/TR/wai-aria-1.2/#aria-current) | A wizard flow, not a numeric stepper (use the Scrubbable number field row for that). The step header is informational, not a tablist; record whether completed steps are directly navigable. Record Back/Next/Finish, per-step validation and focus after failure, polite errors, shortcuts that do not steal text-editing keys in step content, and which dialog or sheet owns focus containment. |
| Viewport | Custom spatial canvas; use [Slider](https://www.w3.org/WAI/ARIA/apg/patterns/slider/) only for exposed scalar controls such as zoom | APG has no pan/zoom canvas pattern. Define focus, keyboard pan/zoom, reset/fit commands, accessible name/description, and a semantic alternative or navigable representation for important drawn content. Support pixel-precise pointer, wheel, and trackpad input. |
| Scrubbable number field | [Spinbutton](https://www.w3.org/WAI/ARIA/apg/patterns/spinbutton/) plus custom pointer scrubbing | Preserve direct text entry and spinbutton arrow semantics. Drag scrubbing, modifier precision, units, and commit/cancel are extensions; provide an accessible keyboard path for every drag-only operation. |
| Precision slider | [Slider](https://www.w3.org/WAI/ARIA/apg/patterns/slider/) plus custom reset/precision interactions | Double-click reset and fine-drag modifiers are extensions. Add a keyboard reset action and keep slider value accessible; do not require pointer dragging for precision. |
| Curve editor | Custom multi-point graph editor; compose [Slider](https://www.w3.org/WAI/ARIA/apg/patterns/slider/) semantics for numeric axes only where useful | Define a keyboard model for point creation, selection, movement/nudging, deletion, channel changes, and interpolation. Expose selected point coordinates and channel; the graph cannot be made accessible by labeling the canvas alone. |
| Colour wheel; colour picker; grading wheels; eyedropper | Custom color selection surface; numeric fields use [Spinbutton](https://www.w3.org/WAI/ARIA/apg/patterns/spinbutton/) and discrete modes may use [Radio Group](https://www.w3.org/WAI/ARIA/apg/patterns/radio/) | Provide equivalent numeric color entry and announcements for hue, saturation, lightness, and color-space values. Eyedropper availability is platform-dependent and must have a keyboard-accessible invocation/cancel path and a numeric alternative. |
| Gradient editor | Custom ordered-stop editor; compose [Listbox](https://www.w3.org/WAI/ARIA/apg/patterns/listbox/) for stop selection and [Spinbutton](https://www.w3.org/WAI/ARIA/apg/patterns/spinbutton/) for position/color values | Specify keyboard add/select/reorder/delete, stop position editing, and selection announcements. Dragging stops must have keyboard equivalents. |
| Histogram | No APG widget pattern; use the [img role](https://www.w3.org/TR/wai-aria-1.2/#img) with a concise text summary, or [Graphics ARIA](https://www.w3.org/TR/graphics-aria-1.0/) if the visualization is navigable | Usually read-only and not focusable. Provide a textual summary/data alternative for channels and clipping; if users can inspect bins, define a separate keyboard interaction model. |
| Property inspector | Compose [Disclosure](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/) for collapsible groups and the pattern of each editor (textbox, checkbox, combobox, spinbutton, slider) | Group headings should expose expanded state. Multi-selection mixed values, reset-to-default, and property navigation are app-specific; announce mixed state and do not invent a monolithic inspector role. |
| Timeline | Custom time-based collection; compose [Slider](https://www.w3.org/WAI/ARIA/apg/patterns/slider/) for playhead/scrubbing and [Grid](https://www.w3.org/WAI/ARIA/apg/patterns/grid/) only for keyboard-navigable track/keyframe cells | Define separate focus and selection for tracks, clips, playhead, and keyframes; include keyboard movement, snapping, zoom, and accessible time/value readout. Drag operations need keyboard equivalents. |
| Node editor | Custom graph editor; compose [Grid](https://www.w3.org/WAI/ARIA/apg/patterns/grid/) only if its cell navigation model fits | Define focus traversal between nodes/ports, selection, connection creation/removal, box selection, and minimap access. Spatial canvas interaction is not covered by APG; every essential operation needs a keyboard path and announced graph relationships. |
| Layer panel | [Tree View](https://www.w3.org/WAI/ARIA/apg/patterns/treeview/) plus Checkbox/Button patterns for visibility and lock | Keep row navigation distinct from toggle-button actions. Specify keyboard reorder and announce position/parent changes; thumbnails need names or descriptions when informative. |
| Command palette | [Combobox](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/) with [Listbox](https://www.w3.org/WAI/ARIA/apg/patterns/listbox/) results | Search text remains editable; arrows browse results, Enter invokes, Escape closes/returns focus. Show shortcuts as descriptions, and do not make them the only way to invoke an action. |
| Shortcut editor | Custom key-capture form; use [Textbox](https://www.w3.org/TR/wai-aria-1.2/#textbox) semantics for captured sequences and [Dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/) if editing in a modal | Specify capture start/stop/cancel, modifier-only input, conflict resolution, and reset. Respect OS-reserved shortcuts; show platform-specific key names and do not capture keys while ordinary text fields are being edited. |
| Laika-seeded slider, histogram, segmented control | Follow the corresponding Slider, Histogram, and Segmented control rows above | Origin does not change conformance: the extracted component adopts the same keyboard, accessibility, and desktop platform decisions. |

## Desktop decisions that specs must make

APG is written primarily for web content. Its interaction patterns remain useful, but GPUI components run in desktop windows and must honor the host platform's text system, focus model, input devices, and shortcut conventions.

- **Focus traversal:** APG's composite widgets often use one Tab stop plus arrow-key navigation. Keep that model for composites such as menus, trees, grids, and toolbars. Ordinary desktop controls remain reachable through logical Tab/Shift+Tab traversal, including when full keyboard access is enabled. See [Apple's keyboard guidance](https://developer.apple.com/design/human-interface-guidelines/keyboards) and [Windows keyboard interaction guidance](https://learn.microsoft.com/en-us/windows/apps/design/input/keyboard-interactions).
- **Text editing and IME:** native text controls own caret movement, selection, undo, clipboard, and input-method composition. A component must not consume those keys merely because an APG composite would use arrow keys for navigation.
- **Shortcuts:** use platform-standard Command shortcuts on macOS and Ctrl/Alt conventions on Windows where applicable. Bind mkit actions through GPUI key contexts so apps can rebind them. Do not steal OS-reserved or standard editing shortcuts. See [Apple's standard keyboard shortcuts](https://developer.apple.com/design/human-interface-guidelines/keyboards#Standard-keyboard-shortcuts) and [Windows keyboard accelerators](https://learn.microsoft.com/en-us/windows/apps/develop/input/keyboard-accelerators).
- **Pointer and trackpad:** desktop controls may support hover, right-click, drag, wheel, and precision trackpad gestures in addition to keyboard operation. These inputs supplement an accessible keyboard path; they do not replace one. Modifiers and gestures can vary by OS and user settings.
- **Menus and windows:** app menu bars, context menus, dialogs, sheets, focus return, and window dismissal interact with the native window manager. State whether a component is an in-window popup, a modal surface, or a platform-owned menu/window; APG web focus rules alone do not settle those choices.
- **Accessibility bridge:** map semantic names, roles, values, relationships, expanded/selected/disabled states, and live announcements into GPUI/AccessKit's platform accessibility tree. ARIA attribute names in APG are conceptual references; specs should use the supported native accessibility properties rather than promise literal ARIA attributes.
